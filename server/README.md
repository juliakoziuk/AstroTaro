# AstroTarot API (NestJS + Sequelize + PostgreSQL)

```bash
cd server && npm install --legacy-peer-deps   # swagger очікує TypeScript 5–6, у проєкті 7
npm run start:dev      # збірка tsc + node dist/main.js → http://localhost:3000/api
npm test               # юніт-тести чистої логіки (таро, сни, астрологія, прогрес)
node scripts/smoke.mjs # наскрізна перевірка всіх ендпоїнтів проти запущеного сервера
```

Swagger: http://localhost:3000/api/docs. Налаштування — у `server/.env` (зразок: `.env.example`); база — PostgreSQL `AstroTarot`.

**Схема бази** — це міграції: `npm run migrate` виконує SQL-файли з `migrations/` по порядку, кожен у своїй транзакції, і записує виконані в таблицю `schema_migrations` (`npm run migrate:status` показує, що ще не застосовано). Зміну схеми додавайте новим файлом `000N_назва.sql`, старі не редагуйте. Порожню базу створює сам `npm run migrate`.
Автосинхронізація з моделей вимкнена, доки в `.env` немає `DB_SYNC=true` (лише для розробки: її `alter` щоразу додавав ще одне `UNIQUE(email)`, такі дублі прибирає міграція `0002`).

**Безпека.**
- Вхід: до 8 невдалих спроб за 15 хв для пари «адреса + пошта» і до 30 спроб з однієї адреси, далі відповідь 429; реєстрація: до 10 за годину з адреси. Лічильники лежать у памʼяті процесу: це для одного екземпляра сервера. За кількох екземплярів лічильники треба винести в спільне сховище, а за зворотним проксі налаштувати `trust proxy`, інакше всі запити матимуть адресу проксі.
- Скидання пароля й підтвердження пошти: `POST /auth/forgot-password` (відповідь однакова для відомої й невідомої пошти, до 3 листів на пошту й 10 запитів з адреси за годину), `/auth/reset-password`, `/auth/verify-email`, `/auth/resend-verification`. У базі лежать лише SHA-256 хеші токенів; посилання на скидання діє годину й одноразове, а після зміни пароля всі раніше видані токени входу стають недійсними. Без `SMTP_URL` лист друкується в консолі сервера разом з посиланням (див. `.env.example`). Підтвердження пошти не блокує вхід.
- Пароль: від 8 символів і не більше 72 байтів у UTF-8 (кирилична літера займає 2 байти), бо bcrypt далі не читає.
- Платні тарифи (`POST /billing/plan`) без підключеної оплати недоступні, вільно обирається лише безкоштовний. `ALLOW_DEMO_BILLING=true` вмикає платні без оплати, лише для розробки.
- Згоди й налаштування зливаються в самій базі (`jsonb ||`), тож одночасні запити не затирають зміни один одного. Заголовки безпеки додає helmet.
- `npm audit` показує 4 помірні попередження про `uuid` (через sequelize), виправлення в пакетів немає. Вразливість стосується лише `uuid` v3/v5/v6 із переданим буфером, а sequelize викликає v4 без буфера.

**Пошук і теги.** `GET /dreams` і `GET /journal` приймають `q` (пошук у назві й тексті без урахування регістру; `%` та `_` шукаються як літери), `tag`, `mood`, період `from`/`to` (кінцева дата включає весь день) і сторінки `limit`/`offset`; кількість усіх знайдених — у заголовку `X-Total-Count`. `GET /dreams/tags` і `GET /journal/tags` повертають теги з кількістю. Записи щоденника мають `tags` (до 10, малими літерами). У полі пошуку екрана снів `#море` означає фільтр за тегом.

**Поділитися розкладом.** `POST /spreads/:id/share` створює публічне посилання (повторний виклик повертає те саме), `DELETE /spreads/:id/share` відкликає його: воно одразу перестає працювати, наступне посилання буде іншим. `GET /shared/:token` без входу віддає розклад, питання й тлумачення без id та даних акаунта; відповідь має `X-Robots-Tag: noindex` і `Cache-Control: no-store`, запитів з однієї адреси не більше 60 за хвилину. Токен — 256 випадкових біт і зберігається в базі як є (посилання треба показувати знову), тож з витоку бази поширені розклади стають доступними: не діліться тим, чого не хочете показати.

**AI-компаньйон.** Відповідь генерує модель з контекстом про людину (профіль, натальна карта, поточне небо, останні сни, розклад, настрій щоденника): `ANTHROPIC_API_KEY` (Claude) або будь-який OpenAI-сумісний сервіс (`LLM_BASE_URL` + `LLM_MODEL`, зокрема Ollama локально безкоштовно). Без моделі, або якщо вона збоїть, відповідає локальний асистент (розпізнає тему повідомлення, пам'ятає тему розмови, не повторюється, реагує на кризові повідомлення контактами допомоги). Відповідь чату містить `source: "ai" | "local"`. Перевірка моделі: `node --env-file=.env scripts/llm-check.mjs`.

Зовнішні API (модуль `cosmos`, усі через сервер із кешем і таймаутом): Nominatim (пошук міста), NASA APOD (`NASA_API_KEY`; публічний DEMO_KEY — лише 10 запитів/год),
ZenQuotes (цитата дня; потрібне посилання на zenquotes.io), sunrise-sunset.org, Nager.Date (свята країни), Met Museum (картини до символів снів, суспільне надбання).
Часові пояси: tz-lookup (координати → зона) + ICU для історичного літнього часу, тож місцевий час народження правильно переводиться в UTC для натальної карти.

Мови (en, uk): клієнт шле заголовок Accept-Language, і сервер віддає все мовою інтерфейсу: назви й тлумачення карт, розклади, трактовку снів, астрологію, відповіді AI-компаньйона (Claude отримує підказку «answer in …»), тарифи, помилки й валідацію.
У базі лежать нейтральні дані (id карт, текст сну), а переклад робиться у відповіді, тож зміна мови перекладає й старі розклади та сни. Мова запиту доступна коду через `currentLocale()` (src/i18n/locale.ts).
Тексти довідників: tarot/cards.ts, tarot/readings.ts, dreams/analysis.ts, astrology/text.ts, companion/reply.ts, plans/plans.ts, i18n/messages.ts.

Модулі за екранами: `auth` (реєстрація, вхід), `dashboard`, `plans` (+ `/billing/plan`), `tarot` (розклади, колоди, витягування карт), `spreads` (історія й «збережені»),
`dreams` (CRUD + автотрактовка), `journal`, `astrology` (натальна карта на astronomy-engine, транзити, фази Місяця, звіти), `companion` + `messages`, `profile` (+ `/settings`).
