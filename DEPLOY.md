# Деплой безкоштовно: Neon + Render + Cloudflare Pages

Три частини, кожна на своєму сервісі:

| Частина | Де | Навіщо окремо |
|---|---|---|
| База PostgreSQL | [Neon](https://neon.com) | безкоштовна без терміну (на Render безкоштовна база видаляється через 30 днів) |
| Бекенд (`server/`) | [Render](https://render.com), безкоштовний web-сервіс | конфігурація вже в `render.yaml` |
| Фронт (`client/`) | [Cloudflare Pages](https://pages.cloudflare.com) | статичні файли на CDN, не засинають |

Репозиторій має бути на GitHub (він уже там: `juliakoziuk/AstroTaro`). Умови безкоштовних тарифів змінюються, тож перед стартом зазирніть на їхні сторінки цін; чи просять ці сервіси картку під час реєстрації, перевірте самі.

## 1. База (Neon)

1. Створіть проєкт, регіон **Frankfurt** (ближче до України й до сервера Render).
2. У розділі підключення скопіюйте **connection string**: `postgresql://…@ep-….neon.tech/neondb?sslmode=require`. Це значення `DATABASE_URL`.
3. Нічого створювати вручну не треба: таблиці створить сервер під час першого запуску (міграції).

## 2. Бекенд (Render)

1. **New → Blueprint**, оберіть репозиторій: Render прочитає `render.yaml`.
2. Заповніть змінні, які він спитає:
   - `DATABASE_URL` з Neon;
   - `CORS_ORIGIN` і `APP_URL`: адреса фронту. Її ви ще не знаєте, тому поставте будь-що (наприклад `https://example.com`), а після кроку 3 виправите.
   - за бажанням `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` (Groq тощо), `NASA_API_KEY`, `SMTP_URL`, `MAIL_FROM`.
3. Після першого запуску відкрийте `https://<ім'я>.onrender.com/api/plans`: має прийти JSON. У журналі видно рядки `applied 0001_…` для кожної міграції.

Що вже налаштовано в `render.yaml`: `TRUST_PROXY=1` (без нього ліміти входу бачили б одну адресу на всіх), `JWT_SECRET` згенерується сам, міграції виконуються перед кожним запуском (повторні нічого не змінюють), `DB_SYNC` і `ALLOW_DEMO_BILLING` вимкнені.

## 3. Фронт (Cloudflare Pages)

1. **Create → Pages → Connect to Git**, той самий репозиторій.
2. Налаштування збірки:
   - Root directory: `client`
   - Build command: `npm run build`
   - Build output directory: `dist`
3. Змінні середовища (Production):
   - `VITE_API_URL` = `https://<ім'я>.onrender.com/api` (**важливо**: вона вшивається під час збірки, тож після зміни потрібна нова збірка);
   - `NODE_VERSION` = `22`.
4. Файл `client/public/_redirects` уже веде корінь сайту на `app.html`, тож відкривати `/app.html` вручну не треба.

## 4. Звести адреси

Поверніться на Render і вкажіть справжню адресу фронту (`https://<проєкт>.pages.dev`, без слеша наприкінці) у `CORS_ORIGIN` і `APP_URL`. Сервер перезапуститься сам.

## 5. Перевірка

- Відкрийте адресу фронту, зареєструйтесь, увійдіть, витягніть карту дня.
- Якщо реєстрація «зависла»: відкрийте консоль браузера. Помилка CORS означає, що `CORS_ORIGIN` не збігається з адресою фронту символ у символ.
- Лист скидання пароля без `SMTP_URL` не прийде: посилання з'явиться в журналі сервера на Render.

## Що варто знати

- **Холодний старт.** Безкоштовний сервіс Render засинає після 15 хвилин без запитів, перший запит потім чекає близько хвилини. Для справжніх користувачів перейдіть на платний тариф, який не засинає (решта лишається безкоштовною).
- **Ліміти в пам'яті.** Лічильники спроб входу й кеші живуть у процесі, тож рахуються для одного екземпляра сервера. Для кількох екземплярів їх треба виносити в спільне сховище (див. `server/README.md`).
- **Stripe.** Лишайте тестовий режим. Для вебхуків вкажіть `https://<ім'я>.onrender.com/api/billing/webhook` і додайте `STRIPE_*` змінні (див. `server/.env.example`). Платні тарифи без оплати не вмикаються, доки `ALLOW_DEMO_BILLING` вимкнений.
- **База.** Безкоштовний Neon: 1 ГБ на проєкт. Коли місце скінчиться, нові записи не пишуться, але нічого не видаляється й не списується.
- **Власний домен** підключається в налаштуваннях Cloudflare Pages; тоді оновіть `CORS_ORIGIN` і `APP_URL`.
