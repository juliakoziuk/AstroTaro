# План вивчення React у цьому проекті

Проект: Vite + React 19. Запуск: `npm run dev`. Точка входу — `src/main.jsx` (там міняємо, який компонент рендериться).

## Що вже є (пройдено)

- Класові компоненти, `this.state`, `setState`, `props` — `src/App.jsx`
- `useState` у функціональних компонентах — `src/App.UseState.jsx`
- Стан у дочірньому компоненті, створений з пропса (підводний камінь) — `src/App.Tricky.jsx`
- Контрольована форма, підняття стану вгору, колбеки — `src/FormExample/AppForm.jsx`

Тож починаємо не з нуля. Нижче — що лишилось, по порядку.

## Правило роботи

Для кожного етапу: **створи окрему папку в `src/`** (наприклад `src/01-basics/`), пиши код сама, а в `main.jsx` підключай поточний компонент. Так старі приклади не губляться.

## Етап 0. Закріпити фундамент (1–2 дні)

Мета: вільно писати функціональні компоненти без підглядання.

- JSX: вирази в `{}`, `className`, фрагменти `<>...</>`, умовний рендер (`&&`, тернарний оператор)
- Props: деструктуризація, `children`, значення за замовчуванням
- Чому не можна мутувати стан (`state.x = 1`) і як працює оновлення через новий об'єкт/масив
- Функціональне оновлення: `setCount(c => c + 1)` — і чому в `App.Tricky.jsx` лічильник не синхронізується

**Практика:** перепиши `App.jsx` (клас `Greeting`) на функціональний компонент з `useState`. Виправ у `App.UseState.jsx` toggle, щоб він справді перемикав (`!prev`).

## Етап 1. Списки та події (2–3 дні)

- Рендер списків через `.map()` і для чого потрібен `key` (не індекс, коли список змінюється)
- Події: `onClick`, `onChange`, `onSubmit`, `e.preventDefault()`
- Робота з масивами в стані: додати, видалити, оновити елемент (`filter`, `map`, spread)

**Практика:** список справ (Todo): додати, видалити, відмітити виконаним. Дані для початку можна взяти з `user.json` (хобі — це готовий список).

## Етап 2. Форми глибше (2 дні)

- Контрольовані vs неконтрольовані поля
- Один обробник на кілька полів (`name` + `[e.target.name]: value`)
- Проста валідація та показ помилок
- `checkbox`, `select`, `textarea`

**Практика:** спрости `RegisterForm` в `AppForm.jsx` — замість двох окремих обробників (`setUserEmail`, `setUserPassword`) зроби один. Додай валідацію email і довжини пароля.

## Етап 3. useEffect та життєвий цикл (3–4 дні)

Найважча тема для початківців — не поспішай.

- Що таке побічний ефект; масив залежностей (`[]`, `[x]`, без масиву)
- Функція очищення (таймери, підписки)
- Як `useEffect` відповідає `componentDidMount / DidUpdate / WillUnmount` з класів (ти це вже знаєш з класів)
- Запит даних через `fetch` + стани `loading` / `error` / `data`
- Не використовувати `useEffect` там, де достатньо обчислити значення під час рендера

**Практика:** годинник з `setInterval` (з очищенням); завантаж список користувачів з https://jsonplaceholder.typicode.com/users і покажи його з індикатором завантаження.

## Етап 4. Інші хуки (3 дні)

- `useRef` — доступ до DOM (фокус на полі), значення, що не викликає перерендер
- `useMemo`, `useCallback` — навіщо (і чому не треба вживати скрізь)
- `useReducer` — коли стан складний (замінює купу `useState`)
- `useContext` — передати дані без «прокидання» пропсів (тема, поточний користувач)

**Практика:** перемикач світлої/темної теми через Context; перепиши Todo з `useState` на `useReducer`.

## Етап 5. Власні хуки та структура коду (2 дні)

- Правила хуків (чому «не можна умовно» — це було в коментарі в `App.UseState.jsx`)
- Власні хуки: `useFetch`, `useLocalStorage`, `useToggle`
- Розбиття на компоненти, структура папок, один компонент — один файл

**Практика:** винеси fetch із етапу 3 у `useFetch(url)`; збережи Todo в `localStorage`.

## Етап 6. Роутинг і стилі (3 дні)

- React Router: `BrowserRouter`, `Routes`, `Route`, `Link`, `useParams`, вкладені маршрути
- Стилі: CSS-модулі (`*.module.css`) — вже підтримуються Vite з коробки

**Практика:** додаток з кількома сторінками: Головна, Todo, Користувачі, Сторінка користувача `/users/:id`.

## Етап 7. Підсумковий міні-проект (1–2 тижні)

Збери все докупи, наприклад «Трекер звичок» або «Нотатки»:

- список + додавання/редагування/видалення
- форма з валідацією
- завантаження/збереження даних (`fetch` або `localStorage`)
- кілька сторінок через роутер
- тема через Context, логіка у власних хуках
